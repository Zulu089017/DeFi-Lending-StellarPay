## Interpretation — do not over-read this run

- Steps 6–13 prove the accounting paths and access control execute on-chain as
  written. They do **not** prove asset custody: no token transfers occur (see
  finding NO-ASSET-CUSTODY in [`../security.md`](../security.md)).
- Steps 14–15 are **failures of the protocol**, recorded deliberately. They are
  the strongest evidence in this repository that liquidation is unsafe.
- A revert is asserted two ways: the simulation traps, **and** a state read
  before/after shows nothing changed. Panic strings are not recoverable from
  release builds (`UnreachableCodeReached` only), so error-message matching is
  not used as evidence.
- Not covered: stale-price rejection (needs ~300 ledgers), and a valid 2-of-3
  bridge attestation (off-chain signer not exercised against these keys).
